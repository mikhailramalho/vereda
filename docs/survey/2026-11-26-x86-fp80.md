# x86_fp80 (80-bit extended precision) support

## Background

On x86 and x86-64 Linux, C `long double` lowers to LLVM's `x86_fp80` type:

- 1 sign bit (bit 79)
- 15-bit biased exponent (bits 78..64, bias 16383)
- 1 explicit integer bit (bit 63: `0` when exponent is 0, `1` otherwise)
- 63-bit fraction (bits 62..0)
- 80-bit (10-byte) store size; 16-byte alloc size on x86-64 (12-byte on x86-32)

Vereda previously rejected `x86_fp80` in `encode/encoder.cpp` (`ieee()` returned `nullptr`)
because `x86_fp80` is not an IEEE-754 interchange format.

## Design

### 79-bit IEEE interchange view

SMT-LIB's `(_ FloatingPoint 15 64)` (camada's `mkFPSort(15, 63, ...)`) has the same
exponent range and 64-bit significand precision as `x86_fp80`, but uses an implicit
leading bit (79 bits total: 1 sign + 15 exponent + 63 fraction).

At bit boundaries (`fp()`, `bits()`, `toBits()`, `fromBits()`, `fpClass()`, `isTrue()`),
`Encoder` converts between the 80-bit `x86_fp80` memory/register representation and the
79-bit IEEE interchange layout:

- `fp80ToIEEE79(bv80)`: converts 80-bit `x86_fp80` to the 79-bit IEEE interchange
  layout while handling non-canonical x87 encodings explicitly: pseudo-denormals
  (`exp == 0`, bit 63 `== 1`) are normalized to `exp == 1` (preserving their exact
  value, e.g. `LDBL_MIN` when `frac == 0`), and unsupported encodings (`exp != 0`,
  bit 63 `== 0`: unnormals, pseudo-infinities, pseudo-NaNs) are mapped to a quiet
  NaN, matching x87 hardware (`#IA` / unordered).
- `ieee79ToFP80(bv79)`: re-insert bit 63 as `ite(exp == 0, 0, 1)` between the 15-bit
  exponent and the 63-bit fraction.
- `Encoder::fresh`: builds a fresh `x86_fp80` from a 79-bit unconstrained symbol passed
  through `ieee79ToFP80`, so bit 63 is canonical by construction and never produces
  unnormal encodings that `APFloat` treats as NaN.

### Always using camada's bit-vector FP encoding for non-interchange formats

Bitwuzla's native `mk_fp_sort` only accepts IEEE interchange formats
(`Float16`, `Float32`, `Float64`, `Float128`) unless built with `--fpexp`; calling
`mkFPSort(15, 63, FPEncoding::Native)` aborts Bitwuzla with an unsupported experimental
format error.

`Encoder::useNative(Type *ty)` therefore restricts native FP theory terms to IEEE
interchange formats (`!ty->isX86_FP80Ty() && !ty->isBFloatTy()`), keeping `x86_fp80`
(and `bfloat`) in `camada::FPEncoding::BV` even when `--fp2bv` is not passed.
Mixed `FPExt` / `FPTrunc` conversions between a native FP type (e.g. `double`) and
`x86_fp80` run in `FPEncoding::BV` via `toBits()` / `fromBits()` so both operands share
one encoding.

### Local initialisation and witnesses

- `nondetLocals` in `src/ir/load.cpp` now includes `x86_fp80` in its scalar set so
  uninitialised `long double` locals receive a scalar nondet symbol.
- `WitnessModuleInfo` in `src/witness/witness.{h,cpp}` recognises `x86_fp80` nondet
  returns and emits exact hexadecimal `long double` literals with an `L` suffix.

## Test impact

- Existing `tests/vereda/float_*long_double*.c` tests now verify `x86_fp80` instead of
  expecting `VERIFICATION UNKNOWN`, joined by `float_long_double_ops.c` (covering
  arithmetic, mixed casts, special values, subnormals, libm intrinsics, and memory
  round-trips under `-m64`, `-m64 --fp2bv`, and `-m32`) and `float_long_double_fail.c`.
- Four imported ESBMC tests (`esbmc-bitwuzla/github_8097`, `github_8097_fail`,
  `github_8097_long_double_32`, `github_8097_long_double_32_fail`) now pass and are
  promoted from `FUTURE` to `CORE`.
- Ten imported ESBMC `FUTURE` tests that previously stopped at `UNKNOWN` on `x86_fp80`
  now reach their missing libm/stdlib models (`cbrtl`, `frexpl`, `ldexpl`, `nextafterl`,
  `strtold`, `fesetround`) and are re-marked from `verdict UNKNOWN` to `verdict FAILED`.
